---
title: "Pattern J — Testing Convention"
description: Convention untuk menulis test di setiap layer — unit test co-located, integration test di $test/, dan E2E dengan Playwright. Termasuk mocking strategy untuk Server Actions dan MSW.
---

## Tujuan

Pattern J mendefinisikan **jenis test yang tepat untuk setiap layer** dalam feature folder. Prinsip utamanya: test harus memverifikasi perilaku yang nyata, bukan implementation detail.

Tiga jenis test dalam konvensi ini:

| Jenis | Scope | Tools |
|-------|-------|-------|
| **Unit / Component test** | Satu file, satu fungsi atau satu komponen | Vitest + RTL |
| **Integration test** | Beberapa layer dalam satu feature | Vitest + MSW |
| **E2E test** | Full user journey di browser | Playwright |

---

## Layer → Test Type

Setiap layer punya jenis test yang sesuai dengan karakteristiknya:

| Layer | Test Type | Catatan |
|-------|-----------|---------|
| `CFN_`, `SFN_` | Unit test | Pure function — mudah di-assert |
| `ZS_` (Zod schema) | Unit test | Assert valid/invalid input shapes |
| `ACT_` (Server Action) | Unit test sebagai pure function | Mock `next/headers`, `next/navigation`, `next/cache` |
| `CE_` (Client Element) | Component test | Gunakan RTL — test dari perspektif user |
| `APIS_`, `APIC_` | Unit test | Mock HTTP via MSW |
| Multi-layer | Integration test | Di `$test/`, gunakan MSW untuk mock API |
| `SE_`, `page.tsx` | E2E | Server Component butuh full runtime — Playwright |

---

## Struktur File

```
app/[feature]/
├── $action/
│   ├── action.submit.ts
│   └── action.submit.test.ts           ← unit test ACT_
├── $element/
│   ├── client.form.tsx
│   └── client.form.test.tsx            ← component test CE_
├── $function/
│   ├── cfn.validate.ts
│   └── cfn.validate.test.ts            ← unit test CFN_
├── $store/
│   ├── ui.store.ts
│   └── ui.store.test.ts                ← unit test store
└── $test/
    └── submit-flow.integration.test.ts ← multi-layer + MSW

api/[feature]/
├── users.ts
└── users.test.ts                       ← unit test APIS_/APIC_ + MSW

e2e/
└── [feature]/
    └── [feature].e2e.ts                ← Playwright E2E
```

Aturan penempatan:
- **Unit / component test** → co-located di samping file sumber, folder yang sama
- **Integration test** → `$test/` dalam feature folder (tidak milik satu file manapun)
- **E2E test** → `/e2e/` di root project, diorganisir per feature
- **Tidak ada `__tests__/` folder** — semua pakai co-located atau `$test/`

## Mocking Strategy

### Server Actions — `vi.mock` untuk Next.js internals

Server Actions bisa di-import langsung dan dipanggil sebagai fungsi biasa. Yang perlu di-mock:

```ts
// Deklarasi vi.mock di level module — sebelum import lain
vi.mock("next/headers", () => ({
    cookies: vi.fn(() => ({
        get: vi.fn(),
        set: vi.fn(),
        delete: vi.fn(),
    })),
    headers: vi.fn(() => new Headers()),
}))

vi.mock("next/navigation", () => ({
    redirect: vi.fn(),
    notFound: vi.fn(),
}))

vi.mock("next/cache", () => ({
    revalidatePath: vi.fn(),
    revalidateTag: vi.fn(),
}))
```

### API Calls — MSW via `src/mocks/node`

Untuk test yang melibatkan HTTP fetch (`APIS_`, `APIC_`), gunakan MSW server dari `src/mocks/node`:

```ts
import { server } from "@/mocks/node"
import { http, HttpResponse } from "msw"

// Setup wajib — tiga lifecycle hooks ini selalu ada bersama
beforeAll(() => server.listen())
afterEach(() => server.resetHandlers()) // ← reset per test, tidak bocor
afterAll(() => server.close())
```

Override handler untuk simulasi error per test:

```ts
it("handles server error", async () => {
    server.use(
        http.get(EP_User.list, () =>
            HttpResponse.json({ message: "Internal Server Error" }, { status: 500 })
        )
    )
    // handler ini hanya aktif di test ini — reset setelah test selesai
})
```

## Contoh

### Unit Test — `CFN_` atau `SFN_`

```ts
// $function/cfn.validate.test.ts
import { describe, it, expect } from "vitest"
import { CFN_ValidateEmail } from "./cfn.validate"

describe("CFN_ValidateEmail", () => {
    it("returns true for valid email", () => {
        expect(CFN_ValidateEmail("user@example.com")).toBe(true)
    })

    it("returns false for invalid email", () => {
        expect(CFN_ValidateEmail("bukan-email")).toBe(false)
    })
})
```

### Unit Test — `ACT_` (Server Action)

```ts
// $action/action.submit.test.ts
import { vi, it, expect, beforeEach } from "vitest"
import { ACT_SubmitLogin } from "./action.submit"

vi.mock("next/headers", () => ({
    cookies: vi.fn(() => ({ get: vi.fn(), set: vi.fn() })),
}))
vi.mock("next/navigation", () => ({
    redirect: vi.fn(),
}))

beforeEach(() => vi.clearAllMocks())

it("redirects to /dashboard on valid credentials", async () => {
    const { redirect } = await import("next/navigation")
    await ACT_SubmitLogin({ email: "user@test.com", password: "valid123" })
    expect(redirect).toHaveBeenCalledWith("/dashboard")
})

it("returns error object on invalid credentials", async () => {
    const result = await ACT_SubmitLogin({ email: "x@x.com", password: "wrong" })
    expect(result?.error).toBeDefined()
})
```

### Component Test — `CE_`

```tsx
// $element/client.form.test.tsx
import { render, screen, fireEvent } from "@testing-library/react"
import { describe, it, expect } from "vitest"
import { CE_LoginForm } from "./client.form"

describe("CE_LoginForm", () => {
    it("shows validation error for invalid email", async () => {
        render(<CE_LoginForm />)

        fireEvent.change(screen.getByRole("textbox", { name: /email/i }), {
            target: { value: "bukan-email" },
        })
        fireEvent.blur(screen.getByRole("textbox", { name: /email/i }))

        expect(await screen.findByText(/format email tidak valid/i)).toBeInTheDocument()
    })

    it("disables submit button while loading", async () => {
        render(<CE_LoginForm />)
        // interact, then assert button state
        const button = screen.getByRole("button", { name: /masuk/i })
        expect(button).not.toBeDisabled()
    })
})
```

### Integration Test — `$test/`

```ts
// $test/login-flow.integration.test.ts
import { vi, it, expect, beforeAll, afterEach, afterAll } from "vitest"
import { server } from "@/mocks/node"
import { http, HttpResponse } from "msw"
import { EP_Auth } from "@/api/auth/auth.endpoint"
import { ACT_SubmitLogin } from "../$action/action.submit"

vi.mock("next/navigation", () => ({ redirect: vi.fn() }))
vi.mock("next/headers", () => ({
    cookies: vi.fn(() => ({ get: vi.fn(), set: vi.fn() })),
}))

beforeAll(() => server.listen())
afterEach(() => server.resetHandlers())
afterAll(() => server.close())

it("sets session cookie and redirects on success", async () => {
    const { redirect } = await import("next/navigation")
    const { cookies } = await import("next/headers")

    await ACT_SubmitLogin({ email: "user@test.com", password: "valid123" })

    expect((cookies as ReturnType<typeof vi.fn>)().set).toHaveBeenCalled()
    expect(redirect).toHaveBeenCalledWith("/dashboard")
})

it("returns error message on 401 response", async () => {
    server.use(
        http.post(EP_Auth.login, () =>
            HttpResponse.json({ message: "Email atau password salah" }, { status: 401 })
        )
    )
    const result = await ACT_SubmitLogin({ email: "x@x.com", password: "wrong" })
    expect(result?.error).toBe("Email atau password salah")
})
```

### E2E Test — Playwright

```ts
// e2e/auth/login.e2e.ts
import { test, expect } from "@playwright/test"

test("user can log in with valid credentials", async ({ page }) => {
    await page.goto("/login")

    await page.getByRole("textbox", { name: /email/i }).fill("user@test.com")
    await page.getByRole("textbox", { name: /password/i }).fill("valid123")
    await page.getByRole("button", { name: /masuk/i }).click()

    await expect(page).toHaveURL("/dashboard")
})

test("shows error message on invalid credentials", async ({ page }) => {
    await page.goto("/login")

    await page.getByRole("textbox", { name: /email/i }).fill("wrong@test.com")
    await page.getByRole("textbox", { name: /password/i }).fill("wrongpass")
    await page.getByRole("button", { name: /masuk/i }).click()

    await expect(page.getByText(/email atau password salah/i)).toBeVisible()
})
```

## Kapan Tidak Pakai Ini

| Situasi | Yang Lebih Tepat |
|---------|-----------------|
| Test Server Component secara isolated | Tidak perlu — cukup E2E |
| Verifikasi tampilan visual/layout | Storybook atau screenshot test |
| Load testing / performance test | k6 atau Lighthouse CI |
| Mock Zustand store di component test | `vi.mock` store atau wrap dengan provider |
